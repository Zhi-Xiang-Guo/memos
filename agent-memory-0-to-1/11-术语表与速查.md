# 11 术语表与速查

## 本章导学

**学习目标**：把全套笔记中的核心概念、指标、不变量和面试问法压缩成可快速复习的索引，并知道哪些词经常被误用。

**使用方式**：第一次学习不要只背本章；完成对应主章后，用这里做回忆测试和面试 flashcards。

## 核心术语

| 术语 | 简明定义 |
|---|---|
| Agent run | 一次从用户输入到回答/动作结束的执行 |
| Harness | 装配 prompt、memory、tools、loop、trace、eval 的宿主系统 |
| Working memory | 当前 run/task 使用的短期状态 |
| Semantic memory | 相对稳定的事实、偏好、约束 |
| Episodic memory | 带时间和上下文的经历/事件 |
| Procedural memory | 可复用行为规则、工作流、Skill |
| Source event | 原始可追溯证据，如一条用户消息/工具事件 |
| Candidate | 从 source 提取、尚未获准成为权威记忆的提议 |
| Authority | 拥有真值、版本、状态与不变量的存储 |
| Projection | 从 authority 派生、可删除重建的 FTS/vector/graph/cache |
| Lineage | 同一 subject-predicate 事实族的稳定身份 |
| Version | 某次不可变的事实解释 |
| Transition | create/reinforce/supersede/conflict/invalidate 等状态演化记录 |
| Provenance | 从 memory 追到来源、模型、策略和操作的链 |
| Scope | tenant/user/project/agent 的可见性边界 |
| Consolidation | 把近期事件批量提炼为较稳定记忆 |
| Reflection | 从轨迹/记忆中总结经验、错误或规则提议 |
| Dreaming | Anthropic 产品中的异步跨 session 记忆重组；通用上属离线反思/整合 |
| Retire | 不再 current 但保留历史 |
| Delete/Erasure | 删除内容及其派生投影，满足用户/政策要求 |
| Tombstone | 不含正文、用于证明删除/阻止复活的标记 |

## 检索术语

| 术语 | 定义/用途 |
|---|---|
| Embedding | 文本到稠密向量的映射 |

| Sparse/lexical | 基于词项、倒排索引、BM25/FTS |

| Retrieval gate | 判断是否需要检索，以及检索什么 |

## 时间术语

| 术语 | 问题 |
|---|---|
| observed_at | 系统何时看到证据？ |
| event_time | 事件何时发生？ |
| valid time | 事实在现实中何时成立？ |

## 指标公式

```text
cos(q,x) = q·x / (||q|| ||x||)

Recall@K = 含所需证据的 query 数 / 全部 query 数

MRR = mean(1 / first_relevant_rank)

RRF(d) = sum_r 1 / (k + rank_r(d))

Precision = TP/(TP+FP)
Recall = TP/(TP+FN)
F1 = 2PR/(P+R)
```

Memory 还应报告：Stale@K、conflict leakage、scope leakage、current/historical/change-time accuracy、abstention F1、freshness、token/cost。

## 技术选型速查

| 条件 | 首选 |
|---|---|
| 几十条、单用户、透明优先 | Markdown 全量注入 |
| 数百条、名字/ID/已知词 | SQLite/PostgreSQL FTS |
| 改写/跨语言/上千片段 | Vector + FTS hybrid |
| 自动决定记什么/更新 | Memory manager |
| 多跳关系占比高 | Graph projection |
| 事实经常变化/问历史 | Versioned temporal authority |
| 多租户/隐私/审计 | PostgreSQL authority + hard scope + deletion workflow |

## Memory vs 微调速查

| 需求 | 方案 |
|---|---|
| 记住某用户今晚 9 点到 | Memory |
| 查公司最新制度 | RAG |
| 永远输出固定 JSON 风格 | Prompt，稳定大规模后可 SFT |
| 提升领域候选提取 | Prompt/eval 后考虑微调 extractor |
| 记住账户余额/订单状态 | 领域数据库/API，不是 Memory |

## 常见误区

- “上了向量库就有记忆” -> 只有语义候选索引。
- “Graph 和 RAG 二选一” -> Graph 可作为表示/遍历，节点/边也可做 RAG。
- “上下文够长就不用 memory” -> 仍缺跨会话治理、更新、删除和固定成本。
- “分数最高就是正确” -> 相关不等于当前/可信/授权。
- “更新就是覆盖旧行” -> 历史查询、审计、late event 会丢失。
- “retire 就是删除” -> retire 保留历史，delete 是内容擦除。
- “LangMem 是数据库” -> 它是 library/manager，store 由调用者提供。
- “Zep 用 graph embedding” -> 需要具体证据；文本 embedding 和拓扑 embedding 不同。
- “processed=true 就可查询” -> hosted pipeline 可能仍有派生延迟，需实测 readiness。
- “模型 JSON 合法就可写” -> schema 不代表权限、真实性、敏感性和幂等。

## 一致性与可靠性术语

| 术语 | 简明定义 | Memory 中的例子 |
|---|---|---|
| Idempotency | 相同逻辑请求重复执行不产生重复可见效果 | 重复 source 不创建两份 memory |
| At-least-once | 任务可能重复，但不会因一次失败永久丢失 | worker retry extraction |
| Exactly-once-visible | 在定义的数据库边界内只出现一个逻辑效果 | effect ledger + unique key |
| Transactional outbox | 业务状态与待处理意图同事务写入 | source 与 materialization job |
| Lease | worker 在一段时间内拥有任务 | claim_until |
| Fencing token | 拒绝过期 owner 晚提交的单调 token | 旧 worker CAS=0 |
| Watermark | 某阶段已覆盖到的权威版本/时间 | projection fresh through version 88 |
| Generation | 一整套可切换的派生投影版本 | embedding generation 7 |
| Shadow | 新配置并行运行但不影响线上决策 | new embedding 只记录结果 |
| Canary | 小流量真实使用新版本 | 1% scope 使用新 reranker |
| RPO/RTO | 可容忍数据丢失窗口/恢复时间 | authority backup 恢复目标 |

## 数据与治理术语

| 术语 | 含义 |
|---|---|
| Trust | 来源可靠程度，不等于模型 confidence |
| Confidence | 对提取/事实判断的不确定性估计，不授予权限 |
| Importance | 未来可能价值的特征，应通过 benchmark 校准 |
| Sensitivity | PII、金融、健康、秘密等治理分类 |
| Cardinality | predicate 是单值还是集合值 |
| Entity resolution | 将 mention 对齐到稳定实体，支持 merge/split |
| Hard filter | 排序前必须满足的 ACL/truth/sensitivity 条件 |
| Quarantine | 未获准进入正常读取路径的隔离状态 |
| Promotion | 将 candidate/generation/private memory 显式提升为可用/共享 |
| Resurrection | 删除内容被旧 job、projection 或备份重新产生 |

## 指标使用条件

| 指标 | 适合 | 不适合/陷阱 |
|---|---|---|
| Recall@K | 是否召回所需证据 | 多证据只命中一个时可能虚高 |
| Complete Recall@K | 多跳/多证据完整覆盖 | 单证据任务与 Recall@K 等价 |
| MRR | 第一条 relevant 越早越好 | 多个证据同等必要时不足 |
| nDCG | 有 graded relevance | 只有二元 label 时意义有限 |
| Stale@K | 当前问题是否泄漏旧事实 | 需明确 incompatible old evidence |
| Answer EM/F1 | 明确答案 | 开放生成/解释性答案 |
| LLM judge | 语义质量补充 | 不能替代 deterministic/人工审计 |
| p95/p99 | 尾延迟 | 样本太少时不稳定 |

## 高频 Flashcards

**Q：为什么 vector DB 不能做 truth？**  
A：相似度不知道 scope、来源、current/history、时间、冲突和删除；vector 应是可重建候选投影。

**Q：为什么旧事实不直接 delete？**  
A：retire 保留曾经为真与变化解释；只有隐私/政策/错误证据等需要 erasure 时才 delete。

**Q：为什么 LLM structured output 仍不可信？**  
A：schema 只验证形状，不验证授权、事实、敏感性、幂等和允许的状态转移。

**Q：为什么 lexical 不能在 vector TopK 内做？**  
A：那会让 vector 成为所有通道的召回上限，精确名字/ID 可能已经被裁掉。

**Q：为什么 Graph 可能不值得？**  
A：多跳收益可能不足以覆盖实体消歧、edge lifecycle、dual-write、删除和运维成本。

**Q：微调和 Memory 怎么选？**  
A：最新、私有、可删事实用 Memory/RAG；稳定行为模式且有数据/评估时才微调。

## 不变量速查

- scope/trust 由可信服务端边界确定。
- model proposal 不直接拥有 authority mutation。
- retained version 不原地覆盖；transition append-only。
- SINGLE current 互斥区间不重叠，冲突须显式。
- projection 可删除、可重建、不可反向写 truth。
- ACL/truth/sensitivity 在 ranking/limit 前生效。
- 删除完成后旧 generation/job 不能复活正文。
- 每个可见 answer evidence 能回到 source。
