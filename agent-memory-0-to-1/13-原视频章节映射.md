## 一条完整复习链

```text
失忆问题
-> 功能分类
-> shape/find/manage
-> 一次 run
-> 文本/SQLite/vector/manager/temporal graph
-> consolidation/retire/reflect/dream
-> 晚宴 control experiment
-> 召回/时序/安全 benchmark
-> 一年生产项目与社招表达
```

## 最终结论

“记忆才是资产”不应理解为把数据锁在某个 SaaS。真正的资产包括：

- 有明确 scope 和 provenance 的原始证据；
- 可版本化、可迁移的权威状态模型；
- 可删除重建的索引与开放导出；
- 能证明质量、成本、安全和限制的 benchmark；
- 团队对何时写、何时读、何时退休、何时忘记的工程判断。

## 分段学习任务

### 0:00-1:52：从失忆到一次完整 Run

**观看问题**：模型参数、当前 context、外部 memory 分别在哪里？Retrieval Gate 为什么存在？工具结果如何回到 loop？

**反例**：“2+2”每次都检索用户记忆，会增加延迟并让无关偏好污染回答；“我上次约 Alex 几点”不检索则必然丢信息。

**产出**：不看视频画一次 run，标出 gate、retrieve、context、LLM、tool、source commit、consolidation 和 trace。

### 2:31-9:47：三支柱与维护

**观看问题**：Shape、Find、Manage 分别由谁负责？RAG 为什么不是存储？retire 为什么不是 delete？

**反例**：项目 star 从 1000 到 1300，旧值曾经真实；Elon 7 点改 9 点，向量相似度无法决定 current。

**产出**：为同一事实分别设计 Markdown、row、vector、graph 表示，并写出 CREATE/SUPERSEDE/HISTORICAL transitions。

### 9:47-17:20：五层实现

**观看问题**：每升一级到底新增什么能力？代价和退出路径是什么？LangMem 为什么不能与 Pinecone 做同维度比较？

**反例**：只有 30 条事实却上三套服务，检索延迟和运维成本高于全量注入；有跨语言需求却只用 FTS。

**产出**：写一页 ADR，包含现阶段方案、拒绝选项、升级触发器、迁移和锁定风险。

### 18:16-26:32：晚宴实验

**观看问题**：相同输入为何各产品 kept 的内容不同？公众人物知识为什么需要 control？accepted/processed/queryable 是否相同？

**反例**：基础模型知道黄仁勋穿皮衣；即使完全没有 memory 也可能答对，因此这不是有效 probe。

**产出**：实现 control、SQLite、vector-only 三个 baseline；保存 required/forbidden evidence、readiness timeline 和 Stale@K。

### 26:32-30:04：Graph 的边界与资产

**观看问题**：那条 edge 的语义、时间、来源是什么？问题是否真的需要 traversal？数据能否导出、重建和删除？

**反例**：图可视化漂亮，但 multi-hop benchmark 没提升；产品 graph 状态无法完整导出，形成锁定。

**产出**：画 entity-edge-source chain，并写 graph go/no-go 指标。

- 能把结论转成自己的架构、测试和项目证据。
