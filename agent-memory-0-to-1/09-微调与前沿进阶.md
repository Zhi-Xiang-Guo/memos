# 09 微调与前沿进阶

## 本章导学

**学习目标**：理解何时应改变上下文、外部状态、检索策略或模型参数，并用数据闭环判断微调、学习型策略、Graph、层级压缩和多模态是否值得引入。

**前置知识**：前 8 章，尤其是分层评估与可复现实验。

**读完产出**：一个微调 go/no-go 决策、训练数据 schema、离线/线上 promotion gate，以及一份前沿机制的可证伪研究 backlog。

## 1. Memory、RAG、微调分别改变什么

| 方法 | 改变位置 | 更新速度 | 逐条溯源/删除 | 最适合 |
|---|---|---:|---:|---|
| Prompt/Context | 本次输入 | 秒 | 强 | 当前任务与短期状态 |
| RAG | 外部证据选择 | 秒-分钟 | 强，取决于存储 | 文档/事实检索 |
| Agent Memory | 受治理的经验状态 | 秒-小时 | 应该强 | 用户、任务、经历演化 |
| Fine-tuning/SFT | 模型参数 | 小时-周 | 弱 | 稳定行为、格式、领域模式 |
| Preference optimization | 参数/策略 | 小时-周 | 弱 | 风格与决策偏好 |

口诀：

- **需要最新、私有、可删除事实 -> Memory/RAG。**
- **需要稳定改变“怎么做”而不是“知道哪条事实” -> 微调。**
- **需要本轮目标/工具结果 -> Context/working state。**

不要用微调记个人欠款、日程或地址：更新慢、难精确删除、容易泄漏，也无法自然表达时间版本。

## 2. 微调如何帮助 Memory 系统

适合微调的是子能力：

- should-remember 分类；
- 结构化候选提取；
- memory type/subject/predicate/temporal interval 标注；
- duplicate/conflict relation 分类；
- query intent/time/entity 解析；
- reranking；
- evidence-grounded answer/abstention。

前提：有高质量标注、稳定任务分布、明确 baseline。先用 prompt + eval 收集失败，再决定微调；否则只是把不清楚的问题写进参数。

微调后仍需确定性 policy。模型即使 confidence 0.99，也不能自行决定 tenant 权限、删除或危险 procedural memory 写入。

## 3. Embedding 微调

### 何时需要

通用 embedding 在领域术语、内部缩写、跨语言或难负样本上 recall 不足，且改 chunk/hybrid/rerank 后仍有稳定缺口。

### 数据

构建 `(query, positive_memory, hard_negative)`：

- hard negative 尤其包括同实体不同时间、旧值与新值、相近项目不同 scope；
- 避免随机负样本过于容易，学不到时序/实体区分；
- train/dev/test 按故事/用户族分组防泄漏。

### 评估

不仅看 Recall@K，还要看 Stale@K、跨语言、scope-filtered recall、ANN 性能、向量维度/存储/成本。微调 embedding 也不能替代 truth filter。

## 4. Learned Memory Policy

前沿方向是让 write/read/forget 策略从长期任务 reward 学习，而非人工阈值：

```text
policy(action | event, state) -> remember/update/ignore/retrieve/forget
reward = downstream utility - cost - privacy/risk penalty
```

难点：reward 延迟、错误自我强化、数据非平稳、可解释性、用户控制和安全约束。生产上更稳的路线是 hybrid：模型/学习策略提出建议，确定性 guardrail 拥有硬约束。

## 5. Self-RAG / Corrective RAG / Adaptive RAG

这些概念都在回答“检索何时、如何自检”：

- **Self-RAG**：模型学习何时检索，并对相关性/支持度进行反思。
- **Corrective RAG**：先评价检索结果质量，不足时改写或换源。
- **Adaptive RAG**：根据问题复杂度路由到无检索、一次检索或多步检索。

它们可以用于 Memory read path，但不自动提供 write/manage lifecycle。评估时应拆出 gate、rewrite、retrieval、critique 每一步。

## 6. Long-term Reflection 与 Dreaming

局部 reflect 看一次轨迹；全局 dreaming/offline consolidation 跨 sessions 重组记忆。前沿关键不只是“模型自己总结”，而是：

- 输入/输出 generation 分离；
- 结果可 review、diff、rollback；
- 记忆库级 benchmark 验证重复、冲突、过时率是否下降；
- reflection 产生的 procedural rule 需验证；
- 防止模型在闭环中放大自己的旧错误。

可设计 shadow dream：新 store 不立即服务线上，在 held-out 问题、隐私扫描、diff 审计通过后再 promote。

## 7. Graph 前沿

### Temporal knowledge graph

实体关系带 event/valid/transaction time，支持 current/as-of/change queries。

### Graph + Vector

向量找入口实体/边，图遍历扩展结构证据，再回到 source text 验证。不要让抽取后的图边丢失原文 provenance。

### Graph embeddings / GNN

node2vec、GraphSAGE、GAT 等编码拓扑或邻域，可用于 link prediction、node similarity。它与“把节点描述文本做 embedding”不同。Agent Memory 只有在拓扑信号本身有预测价值、训练数据足够时才需要。

### Graph 的真正难点

不是 Neo4j 查询语法，而是 entity resolution、关系 schema、时间冲突、来源、删除传播和图投影重建。

## 8. Memory Compression 与层级记忆

长期系统可分层：

```text
raw events -> atomic memories -> session summaries
-> topic/entity summaries -> global compact store
```

每层都要保留指向下层证据的引用。层级检索先粗后细可减少 token，但摘要会漂移；必须能下钻原始证据，并对 compaction generation 做版本管理。

## 9. Multimodal Memory

输入可能是图片、音频、视频、传感器和 UI 操作。推荐：

- 原始媒体存对象存储，Memory 只保留 URI/内容 hash/权限；
- 提取 caption、OCR、speaker、timestamp、region 等派生 evidence；
- 多模态 embedding 是 projection，不替代原始证据；
- 删除必须覆盖原文件、缩略图、转录、embedding 和缓存；
- 人脸/声音等生物特征有更高合规门槛。

## 10. Multi-agent Memory

不是所有 Agent 共享一个全局库。设计：

- private：单 agent/user；
- project/team：显式共享；
- global procedural：高信任、经过验证；
- promotion：私有 -> 共享的受控动作；
- concurrency：optimistic lock 或 subject/predicate 串行化。

多个 Agent 的结论可能冲突；last-write-wins 只是存储策略，不是语义裁决。

## 11. 前沿研究问题

- 如何用下游长期 reward 学习何时写/忘，同时满足审计与用户控制？
- 如何评估记忆在数月积累后的污染、漂移和收益，而非短 benchmark？
- 如何防止 persistent prompt injection 和模型自我强化错误？
- 如何在 privacy erasure 与可审计历史之间建立可证明边界？
- 如何对不确定、矛盾、多来源事实做校准和 abstention？
- 如何让跨模型/跨供应商 memory 可移植，而不被产品 schema 锁定？
- 如何公平计算 Memory 的总成本：形成、维护、检索、生成、存储和人工审核？

## 12. 深度学习路线

1. 先实现可解释 baseline，不追论文名词。
2. 用失败分类收集数据。
3. 只为稳定、重复、可度量的失败增加前沿机制。
4. 用 ablation 证明收益来自何处。
5. 把模型建议与确定性权威边界分开。
6. 对每个新机制写清：能力、代价、失败、回滚、删除、证据。

## 13. 微调 Go/No-Go 决策树

```text
失败是否来自缺少最新/私有事实？
  是 -> 改 Memory/RAG，不微调事实
失败是否来自 prompt/schema/工具 contract 不清？
  是 -> 先修 contract 和 eval
失败是否稳定、重复、分布足够大？
  否 -> 继续收集数据/规则处理
是否有可靠 label、baseline 和 held-out split？
  否 -> 不训练
微调收益是否超过模型锁定、训练和回归成本？
  是 -> 小范围微调 + shadow gate
```

微调不是“进阶必选项”。一个经过验证的 prompt、小模型或 deterministic policy 可能更便宜、更可审计。

## 14. Memory 子任务训练数据

### Write gate / extraction

```json
{
  "source": {"actor": "DIRECT_USER", "text": "...", "time": "..."},
  "context": {"existing_lineages": []},
  "labels": {
    "decision": "REMEMBER",
    "type": "SEMANTIC",
    "subject": "user",
    "predicate": "preference.answer_language",
    "value": "zh-CN",
    "valid_interval": null,
    "sensitivity": ["NONE"]
  }
}
```

### Relation/transition

样本包含 new candidate、existing versions、temporal overlap、cardinality、source trust，label 为 reinforce/supersede/coexist/conflict/invalidate。困难样本比海量简单样本更重要。

### Reranker

保留 query、candidate、truth/time/scope（已授权）、graded relevance。superseded 旧事实可作为 hard negative，但硬 truth filter 仍不应完全交给模型学习。

## 15. 数据质量与泄漏

- 同一用户故事的 paraphrase 不能跨 train/test；
- 同一 source 派生的 chunk/memory 放同一 split；
- 公开 benchmark 可能进入基础模型训练，记录 contamination 风险；
- 人工修正保留 reviewer、一致性和原始 label；
- 不用线上敏感 memory 直接训练，先定义 consent、minimization、retention；
- 合成数据扩大覆盖但不能替代真实错误分布。

训练目标应按场景切片报告，而不是只看 micro average。错误写入在高风险场景的代价可用 cost-sensitive evaluation，而不是简单 accuracy。

## 16. 微调后的系统边界

即使 extractor 已微调：

- JSON/schema 仍做严格验证；
- ACL、sensitivity、state transition 仍由确定性代码；
- 输出记录 model revision 与 dataset lineage；
- rollback 能回到旧 model/prompt/policy；
- 重新处理历史 source 使用新的 semantic job key，不能覆盖旧 run 证据；
- 对输出漂移、拒绝率和 unsupported inference 持续监控。

## 17. Context Caching、Compaction 与 Memory

这些常被混淆：

- **Prompt/context caching**：复用相同前缀计算，降低成本/延迟，不创造状态语义。
- **Compaction**：把当前长轨迹压缩以继续 run，可能写持久 notes，但主要解决窗口预算。
- **Memory**：跨 run 治理状态并选择性召回。

三者可组合：稳定 SOUL/Skills 使用 cache；当前 run 超长时 compact；跨会话事实进入 versioned memory。缓存失效与 memory 删除也要协调，避免被删除正文仍停留在应用级缓存。

## 18. 生成式/潜在 Memory 的边界

研究系统可能使用可训练 memory tokens、KV memory、recurrent state 或外部神经模块。优势是压缩和低显式检索开销；挑战是：

- 难逐条 provenance、解释和删除；
- 跨版本兼容与持久化格式不稳定；
- 用户事实与模型内部状态边界模糊；
- 安全和错误恢复难以证明。

生产个人 memory 通常仍需显式 authority；潜在 memory 可作为派生加速或研究分支，不能直接替代合规真值。

## 19. Learned Policy 的离线到在线闭环

```text
instrument deterministic baseline
-> collect decisions + downstream outcomes
-> counterfactual/off-policy analysis
-> train proposal policy
-> offline replay with hard constraints
-> shadow recommendations
-> human/automatic review
-> limited canary
-> monitor long-horizon contamination
```

短期 answer reward 可能鼓励记住一切，长期会污染。因此 reward 至少考虑 future utility、write precision、staleness、privacy、token/cost 和用户纠正。

## 20. 前沿机制研究卡片

每项新技术用同一模板：

```text
问题：哪个已观察失败？
机制：它改变 write/manage/read/answer 哪一层？
假设：在什么切片改善哪个指标？
Baseline：最简单替代是什么？
代价：延迟/token/存储/运维/隐私？
失败：最坏情况和攻击面？
实验：数据、control、ablation、停止条件？
上线：shadow、promotion、rollback、delete？
```

## 21. 动手练习与验收

### 练习

选择一个稳定失败，例如“中英文 update relation 分类错误”。写出 prompt baseline、数据 schema、hard negatives、split、指标、微调方案、上线 gate 和不应交给模型的硬规则。

### 本章验收

- 能判断一个问题该用 Memory/RAG/prompt/fine-tuning 中哪一个。
- 能设计无故事泄漏的训练/测试 split。
- 能解释微调为何不替代 schema、ACL 和状态机。
- 能区分 caching、compaction、explicit memory 与 latent memory。
- 能把任意前沿技术改写成可证伪实验，而不是趋势介绍。
