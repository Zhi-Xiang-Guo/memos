# Competitive matrix: agent-memory products and primitives

Research cutoff: **2026-08-26**. This comparison is a static evidence synthesis, not a benchmark result. It compares named product/version boundaries; it does not transfer a paper result to newer code, an OSS behavior to a hosted service, or a hosted feature to inspectable OSS source.

Detailed evidence is in the [Mem0](02-mem0-analysis.md), [MemGPT / Letta](03-memgpt-letta-analysis.md), [LangGraph](04-langgraph-analysis.md), and [Zep / Graphiti](05-zep-analysis.md) studies and their [pinned source audits](../source-analysis/README.md). No vendor score is reproduced here.

Framework-level primitives from OpenAI, Google ADK, AutoGen, CrewAI, Semantic Kernel, and Anthropic are compared separately in the [memory landscape](01-memory-landscape.md#what-current-frameworks-establish); they are not silently promoted into the product rows below.

## Evidence and cell legend

The repository-wide fact grades apply without modification:

- `CONFIRMED`: directly supported by official documentation, a paper, pinned source, or a repository-local experiment.
- `INFERRED`: an engineering interpretation consistent with confirmed evidence, but not an upstream guarantee.
- `HYPOTHESIS`: a claim that requires a MemOS experiment.
- `DEPRECATED`: historical behavior or a retired boundary that must not be presented as current.
- `UPSTREAM-REPORTED`: an author/vendor reports a setup or result that MemOS has not independently reproduced.
- `N/E`: not established inside the named review boundary; this is not proof of universal absence.

Matrix cells use these compact marks:

- **C** — `CONFIRMED` first-class behavior in the named boundary.
- **P** — a `CONFIRMED` **primitive, partial implementation, or application-defined hook** exists, but the end-to-end lifecycle capability is not established. `P` is not speculation and must not be read as “probably supported.”
- **U** — only `UPSTREAM-REPORTED` evaluation evidence was reviewed.
- **N/E** — the capability was not established in that boundary.
- **D** — the named product boundary is `DEPRECATED`.

All conclusions following a matrix are explicitly marked `INFERRED` or `HYPOTHESIS` where appropriate.

## What the matrix actually establishes

| Family | Strongest confirmed lesson | Critical boundary/gap for MemOS |
|---|---|---|
| **Mem0** | Fact distillation, explicit scope, and multi-signal retrieval are pragmatic alternatives to replaying transcripts | The paper, current OSS, and Platform implement materially different algorithms; OSS has no authoritative temporal/version model or atomic multi-store write |
| **MemGPT / Letta** | Memory is active context management: retain experience, curate hot context, keep external detail discoverable, and make changes auditable | Git/block edits are useful artifact/version mechanisms, but not structured temporal truth, semantic conflict resolution, or verified privacy erasure |
| **LangGraph / LangMem** | Thread execution can be durable with a verified persistent adapter, and cross-thread storage is a separate primitive; trusted runtime context should own scope | Framework persistence is not a memory policy. LangMem adds formation managers, but base Store/checkpointer claims cannot absorb companion behavior |
| **Graphiti / Zep** | Episodes as provenance, bitemporal fact intervals, and semantic/lexical/graph candidate union directly address changing facts | Probabilistic entity/conflict decisions, ordered non-transactional ingestion, proprietary Cloud internals, and incomplete privacy evidence remain material gaps |

`INFERRED` — These systems are complementary references rather than interchangeable substitutes. Mem0 is the strongest simple fact-memory baseline; Letta is the strongest context-ownership/artifact-memory reference; LangGraph is an orchestration and persistence substrate; Graphiti is the strongest inspectable temporal-graph reference. None of the reviewed boundaries establishes the entire governed lifecycle in [the MemOS problem definition](../architecture/01-problem-definition.md).

## MemOS competitive position and falsifiable claims

The following are project hypotheses, not implemented capabilities:

| MemOS target | Current grade | Required evidence before promotion |
|---|---|---|
| Retained source evidence linked to append-oriented assertion versions/transitions, with governed erasure and policy-permitted non-content tombstones | `HYPOTHESIS` | Schema/invariant tests, replay, provenance trace, correction, hard-delete, and tombstone scenarios |
| Deterministic authorization, idempotency, temporal/state transitions, and destructive actions around LLM proposals | `HYPOTHESIS` | Tenant, duplicate-delivery, concurrency, invalid-transition, and deletion-resurrection tests |
| PostgreSQL authority with FTS/pgvector/graph/cache as rebuildable projections | `HYPOTHESIS` | Failure-recovery spike, reconciliation, rebuild, and measured quality/latency/scale envelope |
| Independent semantic, lexical, entity, and temporal candidates with measured fusion | `HYPOTHESIS` | Held-out retrieval ablations at equal candidate and evidence-token budgets |
| Evidence-bearing context with current/historical/conflict policy and explicit abstention | `HYPOTHESIS` | LongMemEval/LoCoMo plus first-party temporal, contradiction, and abstention cases |
| Verifiable multi-projection deletion with a resurrection guard | `HYPOTHESIS` | End-to-end erase state machine tested against sources, versions, indexes, caches, jobs, and permitted tombstones |
| Better lifecycle quality than full history, rolling summary, raw-vector TopK, and pinned competitor baselines | `HYPOTHESIS` | Reproducible run manifests and raw outputs under the [benchmark plan](../benchmark/plan.md); no claim exists before execution |

`INFERRED` — MemOS should not compete by adding another storage API. Its defensible boundary is a **governed, versioned memory control plane** whose projections and context policy are observable, repairable, and benchmarked. The architecture remains `HYPOTHESIS` until the MVP and benchmark gates produce repository-local evidence.

## Decision for the next phase

- Use pinned **Mem0 OSS V3** as the initial external fact-memory baseline; name Platform separately if it is later tested.
- Use **Letta-style tiered context** as a design reference and potential context-policy ablation, not as the factual source-of-truth schema.
- Use **LangGraph base** only where orchestration/checkpointing helps experiments; do not treat Store persistence as completed memory semantics. Evaluate **LangMem** as a separately pinned companion if it becomes a baseline.
- Prototype **Graphiti-style temporal/entity projection** only after PostgreSQL semantic/lexical/temporal baselines; require a multi-hop gain that justifies entity-resolution and dual-write cost.
- Keep **Zep Cloud** and **Letta hosted API** claims restricted to documented public behavior; benchmark results and operational guarantees require separately declared managed-service configurations.
- Exclude **Zep Community Edition** and retired Letta V1 code from current-product comparisons.

No ranking, quality score, latency number, or production-readiness claim is produced by this matrix.
